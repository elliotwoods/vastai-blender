# Octane rendering

Octane support layers on top of the normal node lifecycle. Its options are in
**Settings → Octane**, and all of them are off by default.

## 1. OctaneBlender: a docker image that has it

Otoy's downloads are login-gated, so the app cannot install OctaneBlender
itself. Octane nodes are rented from a docker image that already has it at
`/usr/local/OctaneBlender/blender`:

- **Settings → Octane → Docker images → Octane nodes** sets the image to rent
  Octane nodes from. The Cycles and EEVEE rows there override the built-in
  image for those engines, and blank means built-in. The built-in image
  (`vastai/base-image:cuda-12.1.1-cudnn8-devel-ubuntu22.04`) has no
  OctaneBlender, so with no Octane image set, Octane work rents nothing. The
  Settings screen says so, and the scheduler raises one warning ("Octane work
  is queued, but … no node is rented for it").
- Before anything else, Octane setup on a node checks that
  `/usr/local/OctaneBlender/blender` is there. If a node rented from the
  Octane image lacks it, the image is at fault, and the job fails with a
  message naming the setting. On any other node (one requested by hand, say)
  it is the node's fault: no render retry is charged, and Octane chunks stay
  off that node.
- The agent never falls back to stock Blender for an Octane job, because stock
  Blender would render the scene with another engine.
- Octane chunks go only to nodes rented for Octane, or to nodes whose rental
  engine the app does not know (requested by hand, or rented before the app
  last started).

## 2. Desktop, VNC and OctaneServer

The first Octane chunk sent to a node that is not yet licensed runs
`remote/octane/setup_octane.sh` on it, which:

- installs a minimal Openbox desktop under TightVNC (skipped when it is
  already installed);
- starts VNC on display `:0`, bound to **localhost only** (port 5900). Its
  **per-node password** is generated by the app, kept in memory for the
  session, and sent on the command's standard input, never in the command
  line;
- starts OctaneServer on that display.

Setup is idempotent. A VNC server already on `:0` is left as it is, never
killed, and an OctaneServer already running is adopted rather than started a
second time. If display `:0` is held by an X server that is not VNC, there is
no way to sign in by hand on that node, and setup says so.

## 3. Signing in to OTOY

### By hand over VNC (the default)

With **sign in by script, with the saved OTOY account** off, your OTOY
password never leaves this computer.

1. OctaneServer starts with nothing on its input, and the app polls its log
   every 5 s. If no license line appears within 60 s, the node reads as
   needing a sign-in. A warning alert names the node ("… is waiting for a
   sign-in: open the node in Fleet, use Open VNC login, and sign in to OTOY
   there …"), and the node shows the *octane sign-in needed* chip.
2. Expand the node in **Fleet** and click **Open VNC login**. The app opens a
   tunnel over the node's existing SSH connection that listens only on
   `127.0.0.1` on this computer. It shows the address
   (`vnc://127.0.0.1:<port>`) and the password, each with a copy button; the
   password stays masked until you click *show*.
3. Point any VNC viewer at the address (on a Mac: Finder › Go › Connect to
   Server), enter the password, and sign in to OTOY in OctaneServer's window
   on the node's desktop.
4. The app checks each Octane node's state every 30 s. Once the server logs
   a license, the node reads as licensed, an info alert says so, and its
   Octane chunks start on their own.

Each node has one tunnel, which closes when the node is destroyed.

**What waits meanwhile.** Every waiting node bills.

- **The chunk.** A chunk on the node waits up to about 11 minutes: the 60 s
  license wait plus 10 minutes for a sign-in. It waits only once per node.
- **If nobody signs in:**
  - The job is held with "Octane waits for a sign-in …", and no retry is
    charged.
  - Octane rentals are paused. The holds banner reads "Octane rentals are
    paused: nobody signed in to Octane on … within 10 min …" and has a
    **Release** button.
  - Both lift when a node becomes licensed. The rental pause also lifts when
    you open a VNC login, on **Release**, and when the app restarts.
  - Nodes that start waiting after a missed sign-in get only the 60 s license
    wait.
- **Rentals.** While signing in is by hand, scale-up keeps at most one Octane
  node waiting for a sign-in (more once nodes are licensed). *+ request node*
  is not limited.

### By script (opt-in)

Turn on **sign in by script, with the saved OTOY account** and save an
account under **OTOY account** (stored encrypted on this computer). The app
then sends the username and password to OctaneServer on its **standard
input**, through the SSH command's stdin:

- They are never in a command line, an environment variable or a file on the
  node.
- OctaneServer is started with no arguments.
- Error messages name the step, never the command.

The host is someone else's machine, and root there can still read a
process's memory. Treat the saved account as disclosed to the owner of every
machine it is sent to.

Two things are not yet verified against a real OctaneServer:

- **Whether a build reads a sign-in on its standard input.** One that does
  not just reads as needing a sign-in, and the VNC sign-in above still works.
- **The exact log lines the app reads as "licensed" and "sign-in failed".**
  The patterns are in `setup_octane.sh`. Until the lines are confirmed, a
  server may stay at *octane starting* after a successful sign-in.

### Datacenter hosts only

**Octane on datacenter (secure cloud) hosts only** rents Octane nodes only
from Vast.ai's datacenter hosts, which means fewer and dearer offers. With it
on:

- the scripted sign-in goes only to a node rented through that filter in this
  session;
- a node the app knows was rented any other way gets no sign-in at all, by
  hand or by script, and its Octane chunks go elsewhere with no retry
  charged;
- a node whose rental the app does not know (one rented before the app last
  started) gets no scripted sign-in, and the sign-in alert warns that the host
  can read what is typed on its desktop.

## 4. License release

Octane floating licenses are released when OctaneServer exits cleanly.
Before the app deletes the instance of a node it can still reach, it stops
OctaneServer first (`setup_octane.sh stop-server`: SIGTERM, a 30 s wait, then
SIGKILL). This covers:

- the Fleet destroy button;
- idle scale-down;
- *clear failed*;
- a failed provision;
- the retry of a failed destroy;
- a quit's *Destroy all & quit*.

The app allows 35 s for the stop on a node where it knows a server ran and
20 s otherwise, and 20 s at most on a quit.

The stop is skipped, and the license stays in use, when:

- the node was lost (it stopped answering, or its SSH connection was gone)
  before the destroy;
- the quit was hurried (a Windows session end, or a console closing on
  Windows);
- you chose *Leave running* on quit, or destroyed an instance from the
  *Unclaimed instances* panel.

A node that destroys itself after losing the app (the node lease, see the
README's Safety model) stops OctaneServer first. After any other case, or if a
machine dies first, release the seat by hand: **Otoy account → licenses →
release all**.
